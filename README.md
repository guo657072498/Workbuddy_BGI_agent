## 用之前：选对模式

| 任务 | 建议 |
|---|---|
| 查资料、读文件、整理本地文件、写草稿 | Craft 模式即可 |
| 生图/生视频、发邮件/消息、写钉钉、发布、删除用户文件/交付物、`git push` | 建议 Plan 模式；保持默认权限，不要开完全访问 |
| 任何「先看方案再决定」的任务 | Plan 模式，第一句写「先给方案，不要执行」 |

模式层控制「开工前要不要给整体方案」，权限层只控制「单步高危操作要不要弹窗」。两者不能互相替代；规则文件也不能替代它们。具体分级与授权判据见 `AGENTS.md` 第 0 节；上表只是使用建议。

## 怎么用这个工作区

**派任务**：把文件（或一个文件夹）丢给我，说明要做什么，我会建一个任务文件夹。涉及生图、发消息、发布、删除、`git push` 这类外部副作用时，我会先给方案或确认卡，等你回话再动手。

**说「归档」**：我按 `docs/ARCHIVE.md` 逐条检查（敏感信息、大文件、目录结构、索引），
通过后提交并推送到 GitHub。归档不移动文件夹。

**改成果**：告诉我哪里要改，我改完同步更新任务 README 和上方索引。

## 目录说明

| 路径 | 说明 |
|---|---|
| `tasks/` | 所有任务，命名 `YYYYMMDD-英文短名`（日期=创建日，永不改） |
| `tasks/_template/` | 新任务 README 骨架 |
| `tools/` | 跨任务共享的工具或运行环境；归属与版本由使用它的任务记录 |
| `AGENTS.md` | 规则源：交互与授权（第 0 节）、身份、命名、目录三分法、状态词、版本管理、提交格式 |
| `docs/ARCHIVE.md` | 归档执行手册（6 步命令） |
| `docs/SECURITY.md` | 敏感信息唯一权威清单 |
| `.workbuddy/memory/` | 工作日志，按日期记录 |

**规范看哪份**：交互与授权 → `AGENTS.md` 第 0 节；命名与目录 → `AGENTS.md`；什么不能提交 → `docs/SECURITY.md`；
归档怎么操作 → `docs/ARCHIVE.md`。本文件只负责索引与用法，**不再重复规则**。
