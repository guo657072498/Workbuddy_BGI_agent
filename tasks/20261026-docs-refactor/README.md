## 目标

原规范的问题不是"不完整"，而是**同一件事写了好几遍，且有三处规则实际不生效**。

1. 根 `README.md` 同时承担索引、用法、命名规则、Git 约定、敏感信息清单，改索引时要小心绕过规范段
2. 敏感信息清单在 README / ARCHIVE.md / .gitignore 三处各写一遍，已经开始不一致
3. `AGENTS.md` 有 40% 内容与 `docs/ARCHIVE.md` 重复
4. `.gitignore` 的 `output/`、`输出结果/` 是任意层级匹配，会静默吞掉将来叫这个名字的交付物
5. `ARCHIVE.md` 3.2 的检查命令**抓不到"`.gitignore` 失效"**——被忽略的文件本来就不出现在 `git add --dry-run` 里

## 关键决策

**规则只写一份，其余用指针。** 这是本次改动的核心原则。代价是多一层跳转，
所以 `AGENTS.md` **保留规则本体**，只把"操作步骤"和"清单明细"外放——避免 AI 只读源文件就动手。

**`.gitignore` 收紧到 `tasks/*/` 前缀。** 根治"通用目录名被误伤"，而不是靠归档时扫描兜底。
