# UDI XML 转 Excel

| 项 | 内容 |
|---|---|
| 创建日期 | 2026-10-26 |
| 类型 | 代码 |
| 状态 | 已完成 |
| 一句话说明 | UDI 系统 XML 转 Excel，免安装 exe，支持压缩包批量，带主数据映射 |

**交付物**：`dist\UDI转换工具-v2.0.0.exe`（约 15 MB 单文件，双击即用，目标机器无需装 Python）

> **版本**：当前 `v2.0.0`。历史版本在 `releases/`，变更记录见 [VERSIONS.md](VERSIONS.md)。
> 升版规则见根目录 `AGENTS.md` 的「交付物版本管理」——**新版本不得覆盖旧版本**。

把 UDI 系统收到的 XML 转成 Excel 明细行。提供两种形态：

- **免安装 exe**（给用户用）：`dist\UDI转换工具-v2.0.0.exe`，单个文件，双击即用
- **源码版**（自己维护）：`python run.py`，便于改字段和调试

## 两类单据

| 单据 | schema 声明 | 结构 | 输出 |
|---|---|---|---|
| **销售出库单** | `终端接口XML Schema-3.0.xsd` | DocHeader + HasProducts + Data | 销售出库明细 / 校验 |
| **生产入库单** | `关联关系XML Schema-3.0.xsd` | Relation + Batch + Code | 盒明细 / 箱汇总 / 码清单 / 校验 |

类型靠 schema 声明 + 结构双重判断，不看文件名。

---

## 一、销售出库单

### 输出文件名 = DN号

一个 XML 对应一个 Excel，文件名取该单的 **DN号**（`DocHeader/@StoreNo`），
一个单据多条明细时取第一条的 DN号。重名自动加 `(2)`，不覆盖已有文件。
DN号 为空时回退到源 xml 文件名。

### 8 列

| # | 列 | 来源 |
|---|---|---|
| 1 | 序号 | 明细顺序 |
| 2 | DN号 | `DocHeader/@StoreNo` |
| 3 | DI码 | `Data/@ProductCode` |
| 4 | 成品名称 | **产品主数据**（按 DI码 查） |
| 5 | 规格(型号) | **产品主数据**（按 DI码 查） |
| 6 | UDI码 | `Data/@Code`，强制文本，30 位 |
| 7 | 供货者 | **法人主数据**（按 `Data/@OwnerCorpID` 查） |
| 8 | 客户名称 | **法人主数据**（按 `Data/@ToCorpID` 查） |

> 机构原始字段里存的是 `A100` / `A080` 这种「字母+3位数字」的机构码，不是名称，
> 所以必须靠法人主数据转换。查不到的留空，并在「校验」sheet 里记一条提示。

## 二、主数据

工具靠两张主数据把编码翻译成中文名：

| 主数据 | 主键 | 用到的列 |
|---|---|---|
| 产品主数据 | 最小销售单元产品标识（UDI） | 产品名称/通用名称 → 成品名称；规格型号 → 规格(型号) |
| 法人主数据 | 法人编码 | 法人名称 |

**存放位置**：`exe 同目录\主数据\产品主数据.xlsx`、`法人主数据.xlsx`。
可以直接用 Excel 打开查看，也可以在工具里改。

**首次启动**：exe 自带一份脱敏种子数据，`主数据\` 不存在时自动写入。
**之后绝不覆盖**：你自己的修改会一直保留。换新版 exe 时，如果新版本内置数据里
有当前没有的条目，会弹窗问要不要合并（只新增，不覆盖）。

### 怎么维护

菜单 **主数据 → 产品主数据 / 法人主数据**，弹出管理窗：

- **上传 Excel…**：批量导入。按表头名自动识别列（全角括号、多余空格都能对上），
  导入前先预览「新增 N 条 / 冲突 M 条 / 相同 K 条」，冲突可选「跳过」或「用导入值覆盖」
- **双击单元格**：直接改，回车生效并立即保存
- **新增一行 / 删除选中行**：删除前二次确认（立即写盘，不可撤销）
- **导出当前数据…**：另存一份给别人
- **打开数据文件**：用 Excel 打开

支持的真实模板格式：

```
产品：《（模版）武汉生科-UDI信息对应-202610.xlsx》
  A:最小销售单元产品标识（UDI） B:大箱标识 C:SAP编码
  D:产品名称/通用名称 E:规格型号 F:特殊储存或操作条件 G:分类

法人：《（模版）法人编码.xlsx》
  A:法人编码 B:法人名称
```

> 产品模板的 7 列**全部存下来**，只是输出 Excel 目前只用到「产品名称/通用名称」和「规格型号」。
> 以后想加列（比如 SAP编码、分类），在 `config/columns.py` 的 `BILL_COLUMNS` 里加一行即可，
> 不用重新导入数据。

## 三、校验规则

### 销售出库单

| 规则 | 级别 | 含义 |
|---|---|---|
| A_DUP_CODE | 错误 | 同单内 UDI 码重复 |
| A_CODE_FORMAT | 警告 | 码不是 30 位纯数字 |
| A_NO_LINES | 错误 | 文件内没有任何明细 |
| M_PRODUCT_NOT_FOUND | 提示 | DI码 未在产品主数据中登记，名称/规格留空 |
| M_CORP_NOT_FOUND | 提示 | 机构编码未在法人主数据中登记，名称留空 |
| X_NO_LINK | 提示 | 出库码在已提供的生产入库单中找不到所属箱码 |

### 生产入库单

| 规则 | 级别 | 含义 |
|---|---|---|
| B_DUP_CODE | 错误 | 码重复 |
| B_PARENT_MISMATCH | 错误 | 盒码 parent 与当前箱码不一致 |
| B_LEADING_ITEM | 错误 | 盒码出现在任何箱码之前 |
| B_ORPHAN_PARENT | 错误 | parent 指向不存在的箱码 |
| B_EMPTY_BOX | 警告 | 箱码下没有盒码 |
| B_CODE_FORMAT | 警告 | 码不是 30 位纯数字 |
| B_CASCADE_INFO | 提示 | cascade 标称比例与实际不符（不参与计算） |

> 原有的 `A_AMOUNT_MISMATCH`（声明数量不符）、`A_UNDECLARED_PRODUCT`（产品未声明）
> 已随「声明数量」「单位」两列一起取消。

## 四、其他使用要点

### 能拖什么

| 类型 | 说明 |
|---|---|
| `.xml` 文件 | 直接处理，可一次拖多个 |
| `.zip` 压缩包 | 自动展开，里面的 xml 全部处理（含子目录、GBK 文件名） |
| 文件夹 | 递归查找里面的 xml 和 zip |

压缩包**不需要手动解压**，程序在内存里直接读。**不支持** `.rar` / `.7z`。

### 30 位码必须存文本

码一律按文本写入（单元格 `@` 格式），否则 Excel 会转成科学计数法丢精度。
写盘后会回读校验，确认码仍是 30 位文本，不通过会在界面标黄并报警。

### 解析要点

生产入库单的码按 **先箱码、后跟该箱盒码** 排列，盒码 `parentCode` 指向当前箱码。
程序严格按 XML 原始顺序切块（遇 `packLayer=2` 开新箱），**不靠流水号推箱内成员**——
实测两箱流水有重叠，用流水号会算错。

`cascade="1:160"` 是标称值，与实际装箱数（75/25）不符，只原样展示、不参与计算。

### 调整 Excel 字段

**只改 `config/columns.py`**，改完重新打包，不用动解析代码。
列元组：`(字段名, 表头, 类型, 宽度)`，类型 `text` / `auto` / `int` / `date`。

## 六、重新打包

双击 `打包exe.bat`，或手动：

```bat
py -3.14 -m PyInstaller --noconfirm --clean udi_tool.spec
```

`打包exe.bat` 会自动检查 `pyinstaller` / `tkinterdnd2` / `openpyxl`，打包完自动跑自检。
**注意它只删旧的 exe，不删整个 `dist`** —— 避免把你跑出来的结果一起删掉。

打包注意事项（踩过的坑）：

1. **`udi_parser/__init__.py` 不能是空文件**——空文件会被当成命名空间包，
   PyInstaller 漏收子模块，运行时抛 `No module named 'udi_parser.source'`。
   `masterdata/__init__.py` 同理，显式 import 了所有子模块。
2. **`Analysis(datas=...)` 是 2 元组 `(源文件, 目标目录)`**，目标目录末尾要带斜杠；
   `a.datas.append(...)` 才是 3 元组 `(目标路径, 源路径, "DATA")`。两者不能混。
   写成 3 元组会报 `too many values to unpack`；顺序写反会拼出 `xxx.xlsx\products.xlsx` 这种坏路径，
   表现为「exe 能跑但主数据是 0 条」。
3. **`openpyxl` 必须打进包里**——零依赖通道只能写 xlsx 不能读，读主数据必需。
4. **日志回调抛异常不能中断转换**——`converter._log` 已包 try/except。

## 七、自检模式

打包后想验证 exe 是否正常，可不打开界面直接跑一次转换：

```bat
set UDI_SELFTEST=E:\out
set UDI_SELFTEST_IN=E:\some\test.xml
UDI转换工具.exe
```

会逐项断言（文件名用 DN号、sheet 数、表头、主数据命中、缺失留空、入库单回归、
30 位文本、主数据非空），结论写到 `<输出目录>\_selftest.log`。
exe 是 `console=False`，控制台看不到输出，**必须看这个日志文件**。

## 九、说明与遗留

**迁移期豁免**：本任务创建于项目规范建立之前，源码直接放在任务根目录，未迁入 `src/`。
按 `AGENTS.md` 的约定，老任务保持原样。

**已知限制**：
- 不支持 `.rar` / `.7z`
- `run.py` 的交互模式里有一个早已失效的默认目录（`办公助理\udi-xml`），当前只影响无参双击，
  拖文件或用 `-i` 不受影响

**cascade 字段待确认**：入库单里 `cascade="1:160"`，实测每箱 75 或 25 盒，两者不符。
程序只原样展示、不参与计算，并在「校验」sheet 给提示。如果业务上确实应该是每箱 160，
可能是数据源的问题，需要回查。

**主数据种子是假数据**：仓库里只放脱敏样例（因为要推 GitHub）。真实数据请用
「上传 Excel」导入到自己的 `主数据\` 目录。
